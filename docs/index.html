designcontext

Do design ao código, sem bagunça

O DesignContext organiza o seu design e entrega ao agente de IA exatamente o contexto que ele precisa para implementar — nada de despejar o arquivo inteiro.

1.O que é o DesignContext

O DesignContext é uma ponte entre o seu design no Figma e o agente de IA que escreve código. Em vez de jogar o design bruto para a IA (que gasta muito e se perde), ele:

🔍 Indexa o que importa

Lê a estrutura do seu Figma e guarda uma versão organizada e leve do design localmente, na sua máquina.

🧠 Responde só o necessário

Quando a IA pergunta sobre uma tela, componente ou mudança, devolve apenas o pedaço relevante — economizando até 70% de contexto.

🔁 Detecta mudanças

Se você alterou só um botão, ele percebe isso e avisa a IA do que mudou — sem reprocessar o design inteiro.

Privado e local Tudo fica salvo na sua máquina, em ~/.designcontext/. Nada é enviado para servidores externos — só há comunicação com o Figma.

2.Requisitos

  • Node.js 22.5 ou superior (baixar aqui).
  • Uma conexão com o Figma — normalmente o Figma MCP que você já usa no seu agente (detectado automaticamente). Token só em último caso.
  • Um terminal (Terminal no Mac, PowerShell no Windows).

Na primeira execução do scan, o DesignContext baixa automaticamente o servidor oficial do Figma MCP (figma-developer-mcp) — por isso a primeira varredura precisa de internet.

Para conferir se você já tem o Node instalado:

$ node --version

3.Instalação

Instale de forma global (uma única vez):

$ npm install -g designcontext

Ou, se você recebeu um arquivo .tgz do time:

$ npm install -g ./designcontext-0.1.0.tgz

Confirme que funcionou:

$ designcontext --version

4.Primeiros passos

1

Inicialize o projeto

Dentro da pasta do seu projeto, rode:

$ cd minha-pasta
$ designcontext init

Isso cria uma pasta .designcontext/ com a configuração do projeto.

2

Conecte o Figma

O DesignContext reaproveita o Figma MCP que você já usa no seu agente — normalmente nenhum token é necessário:

$ designcontext connect

Se preferir, dá para apontar para um Figma MCP hospedado ou usar um token:

$ designcontext connect --url https://seu-host/mcp
$ designcontext connect --file <idDoArquivo> --token <seuToken>
3

Indexe uma tela (scan)

Escaneie o arquivo inteiro ou só uma tela específica:

$ designcontext scan                      # documento inteiro
$ designcontext scan --node 123:456        # só uma tela/componente

Aqui o DesignContext abre o Figma MCP, lê o design e guarda a versão organizada localmente. Na primeira vez ele faz um scan completo; nas próximas, já detecta só o que mudou.

4

Pronto — o agente já consegue usar

Com o servidor MCP no ar, a IA passa a consultar o design sozinha. Veja a seção de integração.

5.Referência de comandos

ComandoO que faz
init [nome]Cria a pasta .designcontext/ com a configuração do projeto.
connectConfigura a conexão com o Figma e guarda as credenciais no cofre do sistema.
scanIndexa o escopo do projeto. Aceita --node <id> e --incremental.
statusMostra telas, componentes e tokens indexados, além do tamanho do cache.
diff [tela]Mostra só o que mudou desde o último scan.
inspectImprime o contexto de um nó em um nível (0 = resumo … 4 = bruto).
clear-cacheLimpa o cache local (mantém a configuração do projeto).
mcpInicia o servidor MCP para o agente de IA.

Para ver todas as opções de qualquer comando:

$ designcontext <comando> --help

6.Integração com o agente de IA

O DesignContext funciona como um servidor MCP. Basta registrar o comando abaixo na configuração do seu agente (Claude, Codex, etc.): 

{
  "mcpServers": {
    "design-context": {
      "command": "designcontext",
      "args": ["mcp"]
    }
  }
}

Com isso, o agente ganha ferramentas para consultar o design sem que você precise copiar e colar nada:

FerramentaO que entrega
design_get_screenResumo de uma tela (seções, componentes, layout, filhos disponíveis).
design_get_structureA árvore de um nó até a profundidade pedida.
design_get_componentDetalhe completo de um componente (estrutura, propriedades, tokens, mapeamento de código).
design_get_tokensTokens de estilo (cores, espaçamentos, tipografia) de um escopo.
design_get_changesSó o que mudou desde a última versão.
design_findBusca por nome de tela ou componente.
design_inspectAprofunda o contexto de um nó, nível a nível.
Como isso aparece no dia a dia Você pede: "implemente a tela Checkout do Figma". O agente chama design_get_screen, recebe só o resumo da tela e os componentes envolvidos — e implementa com o contexto certo.

7.Perguntas frequentes

Preciso entender de banco de dados ou de código?

Não. Você só precisa dos comandos init, connect e scan. O resto é automático.

Meus dados vão para algum servidor?

Não. Tudo fica local, em ~/.designcontext/. A única comunicação externa é com o Figma, para ler o design.

O que acontece se eu mudar uma tela no Figma?

Rode designcontext scan de novo. Ele detecta só o que mudou e a IA fica sabendo exatamente o que foi alterado.

O que é "scan incremental"?

É o scan rápido: em vez de reprocessar tudo, ele compara e só atualiza os nós que mudaram. É o comportamento padrão após o primeiro scan.

O que preciso para conectar ao Figma?

Na maioria dos casos, nada além de rodar designcontext connect: ele detecta o Figma MCP que você já tem configurado no seu agente e reaproveita. Se não houver, dá para apontar para um Figma MCP hospedado (--url) ou usar um token do Figma.

Onde ficam as credenciais do Figma?

No cofre seguro do sistema operacional (Keychain no macOS, Credential Manager no Windows). Nunca em arquivos do projeto.
